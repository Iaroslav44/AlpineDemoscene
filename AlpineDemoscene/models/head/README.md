# GANHead: pretrained geometry, appearance and expression fields

This is a local research integration of the authors' public pretrained GANHead
checkpoint, trained on textured FaceVerse scans of real people.

- Official project: https://github.com/wsj-sjtu/GANHead
- Repository version inspected: `76c98ce18f940caf6aec4cf620df8f8d2bc788b6`.
- Author-linked archive:
  https://drive.google.com/file/d/1ztHGU9GdCoMkAlQB7ynoztIFewVaILlQ/view
- Checkpoint member: `model_and_data/stage2_model/checkpoints/last.ckpt`.
- Source checkpoint: 82,158,734 bytes, SHA-256
  `03ef6010ee1b2a81d64c0728d32b578eb1170a05aabc672a4b2f60a5d10e86ce`.

The checkpoint is read by a restricted whitelist reader which does not execute
Python checkpoint globals. Its optimizer, training examples and all FLAME
template geometry/regressors/landmark tables are excluded from the runtime
export. The runtime consumes seed-derived latent vectors and 3D coordinates;
there is no source photograph or stored head mesh.

`ganhead-faceverse.json` contains the exact final tensor ranges and checksum.
The format shares the NAV1 tensor layout with gDNA but uses magic **NAH1**, so
the runtime cannot accidentally interpret head parameters as a body decoder.

## Learned graph

The shape latent has 256 components; detail has 128 and appearance has 256.
The learned 3D feature generator uses the same convolution architecture as gDNA.
The occupancy network samples this field at the original head coordinates,
without gDNA's body-coordinate normalization. An eight-hidden-layer normal
decoder and a separate eight-hidden-layer appearance decoder generate surface
normals and RGB. RGB is the network's learned photographic surface color,
mapped from [-1,1] to [0,1]; it is not independently established PBR albedo. The
renderer converts these sRGB-like values to linear light before illumination.

The learned five-joint deformation network also predicts 50 expression and 36
pose corrective direction fields. Neither the learned appearance nor the
deformations are manually substituted with a formula-generated face.

## Captured-expression controls

The author archive includes fitted IMavatar `yufeng_1812` numeric sequences.
Only its **1,825 NPY arrays of 169 numbers** are fetched, using a 1.76-MB ZIP
range. No accompanying photograph is fetched or packaged for this path.

The normalized source numeric array has SHA-256
`80a048a1abc7340612e84691e358cc8723d1c9091234e0623713a06c78254a76`.
The last 50 values of each frame are expression coefficients. Four PCA modes
retain **86.2354%** of their centered variance. The corresponding neural output
weights are algebraically projected onto those four modes; actual per-vertex
deformation directions are still generated by inference at startup.

The identity-fitting mean is omitted. The first and last 24 frames are blended
to a common endpoint, and the sequence is retimed to the demo's 128 seconds.
This is a compact approximation to captured expression variation, not an exact
reproduction of the full recording. Relative jaw pose is preserved separately
for a future verified jaw transform; it is not silently applied as an arbitrary
expression mode. No semantic labels are invented for the PCA modes.

## Runtime contract

`NeuralAvatarCreate` recognizes NAH1. Its 96-byte result preserves the original
first 64 bytes and adds a generated motion buffer/SRV, frame count, vertex
stride and motion duration. Body vertices remain 64 bytes. Head vertices are
144 bytes, nine `float4` records:

1. Position, generated and scaled to 0.33 m total height, neck minimum Y=0.
2. Learned normal.
3. Four joint indices, stored as raw unsigned integer bits.
4. Four normalized weights.
5. Learned RGB in [0,1], with W=1.
6. Four consecutive learned expression-direction `float4`s, XYZ in metres.

The head motion SRV holds two `float4`s per frame: four expression coefficients,
then three relative jaw axis-angle values plus padding. Expressions are applied
by the renderer each frame. Normals are currently the canonical learned normals;
expression-dependent normal corrections and accurate eye/jaw rigs remain
limitations of this integration.

Canonical coordinates are Y-up with the face looking toward positive Z. The
mesh includes a short neck/collar region; the total 0.33-m height includes that
region. Its first checked seed has bounds X=[-0.16135,0.16445] m and
Z=[-0.13601,0.11450] m. These are generated bounds, not a hand-built face shape.

Mesh extraction removes disconnected surface islands before scale/bounds are
computed. That postprocess changes neither neural weights nor field evaluation.

## Reproduction and rights

`tools/neural_head_export.py --download` range-fetches the selected checkpoint
and numeric motion only, verifies pinned hashes, folds weight normalization and
the four expression projections, and writes the compact export.
`tools/neural_head_reference.py` provides an independent NumPy graph for
comparison with diagnostic GPU arrays.

No explicit license for GANHead's code or checkpoint was found in its repository
or model archive. Their public download is recorded as provenance, not as proof
of unrestricted redistribution rights. This integration is a local research
evaluation; no public publication/upload has been performed or authorized by
this file. Dataset, checkpoint, FLAME and code terms must not be conflated.

This model improves the project's actual neural face generation. It does not
establish cinematic photorealism, physically separated skin materials, or a
complete muscular/ocular facial simulation.
